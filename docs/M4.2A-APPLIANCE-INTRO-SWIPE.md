# M4.2a — Appliance Intro + Swipe Restoration

This increment pauses web-surface expansion and rounds out the appliance first.

## Visual baseline

- True black background is the appliance baseline.
- Intro page is deliberately minimal.
- `PRISMA` is white.
- `-PI` uses the approved animated multicolor sweep.
- `LITE` is smaller and white.
- `VIDEO SYNTHESIZER` is white and lower/right aligned.
- No version/build/network text is shown on the intro.
- Four page indicators remain at the bottom.

## Intro interaction

- A short tap on page 1 adds the validated cumulative glitch/pixel-block treatment.
- A horizontal swipe changes page.
- A short tap must not be interpreted as navigation.

## Swipe model

The previous M4.1 loop forwarded only touch-down. M4.2a restores continuous touch tracking:

1. capture touch-down position;
2. track coordinates while the finger remains down;
3. decide the gesture only when the finger is released;
4. require horizontal dominance and a minimum displacement;
5. clamp navigation to pages 1..4;
6. reserve slider zones for parameter drag so slider movement is not misread as page navigation.

Current thresholds:
- horizontal displacement: 36 px minimum;
- vertical displacement: 72 px maximum;
- horizontal axis must exceed vertical movement by at least 12 px.

## Shared-state rule

Page selection is written through `prisma_app_set_page()`, so the appliance remains compatible with the bidirectional web synchronization planned for M4.2.

## Scope

This increment intentionally does not redesign pages 2–4. Their backgrounds inherit black now; detailed visual polishing follows page by page after page 1 and gesture behavior are validated on hardware.
