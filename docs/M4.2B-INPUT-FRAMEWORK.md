# M4.2b — Appliance Input Framework

This increment stabilizes the appliance interaction framework before pages 2–4 receive further visual work.

## Navigation contract

Page navigation is physical-button-first:

- T1 / back: GPIO0, active low.
- T2 / forward: GPIO4, active low.
- GPIO5 remains the power button and is not repurposed.

These assignments follow the official Waveshare factory firmware for ESP32-S3-Touch-LCD-1.54. The factory firmware uses GPIO0 to move to the previous tile and GPIO4 to move to the next tile.

Navigation is clamped to pages 1..4. There is no wrap from page 4 to page 1 or page 1 to page 4.

## Debounce

Buttons are sampled in the 20 ms appliance loop and require two consecutive matching samples before a state transition is accepted. Navigation occurs only on the stable pressed edge, so holding a button does not repeatedly change pages.

## Touch/gesture contract

Touch remains continuously sampled while the finger is down. The gesture layer keeps the M4.2a thresholds:

- horizontal displacement: 36 px minimum;
- vertical displacement: 72 px maximum;
- horizontal movement must exceed vertical movement by at least 12 px.

Horizontal swipes are detected and exposed as gesture events, but they no longer change pages. This reserves the gesture engine for later parameter/control interactions without coupling it to navigation.

Slider zones continue to consume drag input directly and are excluded from swipe classification.

## Page 1

The approved page-1 visual baseline remains unchanged:

- true black background;
- white PRISMA wordmark;
- animated multicolor sweep over -PI;
- white LITE and VIDEO SYNTHESIZER;
- four page indicators;
- short tap adds the cumulative glitch treatment.

## Shared state

T1/T2 navigation still writes through prisma_app_set_page(), so future web synchronization sees the same active page as the appliance.
