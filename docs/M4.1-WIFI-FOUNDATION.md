# M4.1 — Local Wi-Fi Foundation

## Decision
PRISMA-PI Lite is local-first. This milestone does not require a router or Internet connection.

## Implemented behavior
- ESP32-S3 starts an autonomous Wi-Fi access point on boot.
- SSID: `PRISMA-PI-LITE`.
- Default local address: `192.168.4.1`.
- Current AP is intentionally open for prototype testing.
- Local HTTP server starts with the AP.
- `/` currently serves a minimal connectivity placeholder; it will become the four-page Vintage synthesizer UI.
- `/api/v1/network/status` exposes local AP state.
- `/api/v1/health` exposes a minimal health check.
- Client join/leave count is tracked.
- Network failure is nonfatal: display, touch and appliance UI continue.

## Explicitly deferred
The following are not part of M4.1 runtime behavior:
- joining a home/office Wi-Fi network;
- Internet access;
- SSID/password provisioning;
- STA retry/fallback behavior;
- cloud services;
- full `/admin`;
- full web synthesizer `/`;
- WebSocket bidirectional state sync;
- live video streaming.

A future uplink/STA configuration may be added under `/admin > Network`. It must remain optional: the appliance must continue to work as a self-contained local device.

## M4.1 acceptance test
1. Boot the appliance with no router available.
2. Confirm SSID `PRISMA-PI-LITE` is visible.
3. Connect a phone/computer to that SSID.
4. Open `http://192.168.4.1`.
5. Confirm the local PRISMA connectivity page loads.
6. Confirm `/api/v1/network/status` returns `mode=local_ap` and the client count.
7. Disconnect/reconnect the browser client and confirm the appliance UI remains responsive.
